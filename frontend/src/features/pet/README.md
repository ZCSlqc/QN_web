# 六一的小窝

入口：导航“爱的小窝”，路由 `/pet`。页面在 `src/views/PetView.vue`，请求/同步在 `usePet.js`，未确认投喂在 `pendingFeed.js`。

## 页面分工

- 互动卡片统一放摸摸头、逗一逗；访客还可看自己的猫条、送祝福和投喂。
- “我们的小背包”独立展示，仅管理员可见；只有配置好的管理员情侣双方可消耗。
- 背包仅展示合计，不展示自己/对方各有多少。文案：**两个人一起攒，一起花**。
- 规则提示：**新照片 → 猫条 · 完成心愿 → 猫粮 · 完成旅程 → 罐头**。

## 库存和奖励

- 管理员不能通过祝福留言获取或使用访客猫条。
- 访客每天首次成功提交首页祝福获得1根，按服务端北京时间计算；信箱留言、心愿感想不计入。
- 管理员情侣新上传照片获得猫条，首次完成心愿获得猫粮，登记已完成旅程获得罐头。预定旅程和未来返程日期不提前奖励；返程日期到达后保存该记录可结算。
- 每个来源只结算一次，删除/修改/重复完成/接口重试不重复奖励；新上传的相同原始文件哈希也不重复发猫条。
- 旧行程、已有照片、已完成心愿标记为历史来源，不批量补发；尚未完成的旧心愿以后首次完成可获得猫粮。
- 两人合计展示，按账号分别记账；每次投喂先扣操作者自己的同类食物，为0时扣另一半的，扣除和流水在同一个事务。

## 昵称

用户名和权限不变，记录展示昵称。李琪淳默认为琪琪，郑丹妮默认为妮妮；账号设置支持自行修改昵称。后台用户名后有独立昵称列。祝福、心愿贡献人、信件及宠物投喂展示最新昵称。

## 重试和会话

未确认投喂的 request_key、食物类型和当前账号ID保存在 sessionStorage。刷新或往返页面后先确认上一笔，不再次扣除；切换账号不会读取另一个账号的待确认操作，退出登录会清理当前会话标识。浏览器不允许会话存储时暂停新投喂，防止无法确认的重试。

## 素材与范围

`public/pet/liuyi/` 为透明WebP；写实版参考 `../QN_web_materials/cat/六一.jpeg`，插画版参考 `../QN_web_materials/cat/六一A.jpeg`。原始输出在 `../QN_web_materials/cat/generated/`。两套形象共用六一的数据，选择只在当前浏览器记住。

不做离线惩罚、死亡、商城或每日签到压力。两种形象共用四帧步态、互动和睡觉状态。

后端实现：`services/rewards.py`（访客祝福奖励）、`services/pet_wallets.py`（情侣来源与账户库存）、`services/pet.py`（投喂与状态）。


## 互动与版式优化

- 标题、正文和留白参考爱的旅程：1100px容器、28–42px栏目标题、14–16px正文、12px说明；上方完整场景，下方互动和背包。
- `FoodIcon.vue` 使用用户提供的三个食物 PNG 图标，背包、投喂反馈和日常记录共用。
- `CatSprite.vue` 根据状态切换图片：0安静、1眯眼、2伸爪、3低头。两种风格各4张，提前解码，相同脚底基线，不旋转或拉伸整张猫图。
- `useCatInteraction.js` 管理动作和时机。同一种动作连续点击不重启，进食期间不重复触发；闲置时偶尔短暂眨眼，页面不可见时暂停。
- 逗猫棒跟随场景内的鼠标或触摸位置；摸头支持点击或轻划。提示气泡出现约3秒后收起。
- `pet.css` 集中页面样式。减少动态效果模式禁用过渡和装饰动画，仍可主动切换姿态。
- 奖励说明：`上传新照片 → 猫条 | 完成心愿 → 猫粮 | 完成旅程 → 罐头`。

动作参考原图保留在外部归档 `../QN_web_materials/cat/generated/*-poses.png`；网页使用单独对齐的 `public/pet/liuyi/*-pose-0..3.webp`，原静态图作为加载失败时的回退。素材预处理脚本为 `node frontend/scripts/prepare-pet-poses.cjs`。


## 食物图标与写实场景素材

界面图标采用用户提供的 `docs/猫条.png`、`docs/猫粮.png`、`docs/猫罐头.png`，原文件不改。发布资源重命名为 `public/pet/liuyi/icons/cat-treat.png`、`cat-food.png`、`cat-can.png`，由 `FoodIcon.vue` 用于背包、访客投喂按钮及日常记录。

`FeedingProps.vue` 单独控制场景物件：空碗 `bowl-empty.webp`、满粮碗 `bowl-full.webp`、打开罐头 `can-open.webp`、撕开猫条 `treat-open.webp`，均位于 `public/pet/liuyi/food/`。原始生成 PNG 保留在 `../QN_web_materials/cat/generated/food/`；页面加载压缩后且保留 alpha 的 WebP，避免加载多MB原图。空碗和满碗采用相同参考、视角和布局；素材预加载后交叉显示，投喂完成恢复空碗。素材失败时保留简单碗形回退。

鼠标靠近猫身时显示场景内的写实抚摸手，按住轻划触发眯眼。真实手图层不拦截事件，离开猫咪区域恢复默认光标；触屏不显示悬浮手。逗猫棒使用手持棒的写实透明图片，玩具老鼠使用原 icon。

## 散步、午睡和玩具

- `useCatWalk.js`：闲置15–30秒走一小段，65px/s、每帧160ms；两版共用位置和帧序，切换风格不重置。点击地面可指定位置，摸头会停下，投喂后走回食盆。移动端按猫图实际占宽限制范围。
- `useCatLife.js`：清醒60–90秒后自主回猫窝睡觉，睡眠同样持续60–90秒。窝口仅显示闭眼枕着爪子的头，轻微呼吸和 zzZ；点击睡猫、摸头、玩具或成功投喂可唤醒。
- 老鼠沿地面跑动、停顿、转向，六一跟随，到达后伸爪；每轮12秒。切换玩具、睡觉、投喂、离开视口会清理本轮定时器。
- 页面隐藏时暂停；减少动态效果模式不自动散步、不连续追逐，保留主动交互。
- 睡姿：`public/pet/liuyi/liuyi-{realistic,illustrated}-sleep.webp`；手：`public/pet/liuyi/interaction/hand-{pet,teaser}.webp`。原始图和生成说明见外部归档 `../QN_web_materials/cat/generated/`。
- 预处理：`node frontend/scripts/prepare-cat-walk.cjs`、`node frontend/scripts/prepare-cat-life.cjs`，仅做透明图片的尺寸、帧基线与 WebP 发布处理。
- 回归：`test/e2e/test_pet_life.mjs` 覆盖切换风格保留步态、睡觉唤醒投喂、真实手、老鼠地面运动及320px屏幕。

鼠标仅使用普通箭头、按钮点击手和真实图片手；逗猫棒模式隐藏场景内系统光标，按钮仍可点击。旧 `public/pet/liuyi/cursors` 已删除。玩具老鼠原图朝左，向右时翻转，场景尺寸84×64px（原尺寸两倍）。猫条居中放在餐盘上方。

## 昼夜、进食与作息

- `useRoomTime.js` 使用UTC+8计算北京时间：06:00起白天，18:00起夜晚；分钟边界与恢复页面可见时校准，不依赖设备时区。夜间窗外月亮、深蓝天空，室内调暗，按钮文字维持对比度。
- 成功投喂后先走回食盆，准备450ms后开始进食：猫条4秒、猫粮7秒、罐头10秒，最后600ms抬头。期间禁用重复投喂与玩耍。
- 无人干预时清醒和睡觉各随机60–90秒，约各占一半；回窝步行额外计时。互动优先，主动互动后重新安排休息，离开视口暂停计时。
- 台词覆盖摸头、散步、追鼠、伸爪、开饭、进食、吃完、犯困与醒来。普通阶段台词间隔至少3.2秒，气泡每句3秒；睡着仅显示zzZ。左下角显示“六一小朋友·当前状态”。
- `test/e2e/test_pet_routine.mjs` 用虚拟时钟验证6点/18点切换、三种进食时长、自动入睡及醒来。

## 共享天气与恢复行为

- 管理员通过窗边晴雨按钮设置天气，`PUT /pet/weather` 接收 sunny/rainy，保存在 SQLite 的 pet_environment 表；其他访客只读。所有客户端通过现有30秒状态轮询同步，刷新后保留。后端启动幂等创建表，默认为晴天。
- 雨仅显示在窗内，不自动播放声音；便签随晴雨、昼夜切换，普通阶段会回应天气变化。气泡跟随六一的水平位置并限制在场景内。
- 回窝使用专用到达范围与缩小过渡；醒来恢复尺寸。作息离开视口后保留剩余时间，回到场景继续。
- 已成功扣粮的待进食回调在离开视口时保留，回到场景继续走向食盆，不再次请求投喂。
- 再点当前玩具可收起；持续移动逗猫棒会延长互动，停止移动后结束。日常记录不再显示食物属于谁。
- 回归：backend/test/test_pet.py 与 frontend/test/e2e/test_pet_weather.mjs。

天气按钮改为窗台下方一排三个小图标：`public/pet/liuyi/weather/sunny.png`、`cloudy.png`、`rainy.png`，分别复制自 `../QN_web_materials/cat/1/晴天 (1).png`、`阴天 (1).png`、`雨情信息.png`，原文件保留。支持阴天及旧晴雨设置表的无损升级。窗外云朵分层缓慢漂移，雨丝有不同长度、速度和透明度，少量玻璃水滴缓慢滑落；夜间使用灰蓝雨丝并遮住月亮。

回窝缩小按实际移动距离插值，同时向窝口上移，不再入睡前瞬间缩小；暂停恢复保留同一段移动进度。天气按钮无圆形背景，位于六一后方，允许自然遮挡；雨天使用乌云，夜雨云层进一步变暗。

室内天气亮度：晴天维持原样，阴天稍暗、雨天更暗；背景、地板、摆设和猫咪分别调节，保留文字和按钮的可读性。夜间同样按晴、阴、雨逐档调暗。

## 猫爬架与饮水

`CatFurniture.vue` 绘制窗前的绳柱猫爬架和清水盆，层级高于六一，可形成自然遮挡，跟随天气调节亮度。手机端缩小家具并将水盆与食盆分开。

`useCatWater.js` 在清醒30–45秒后安排一次饮水：走到盆边，用低头姿态喝4.5秒，水面出现轻微涟漪，随后继续活动。每个睡醒周期最多一次；饮水暂时暂停原有休息倒计时，结束后继续剩余时间，不无限推迟睡觉。摸头、玩具、成功投喂可打断；离开视口取消本次饮水。饮水不调用投喂接口，也不扣任何库存。两种风格共用行为。

浏览器回归：`test/e2e/test_pet_water.mjs`，覆盖前景层级、自动喝水、姿态、水纹、库存不变及手机布局。

## 奖励到账动画与写信猫条

- `rewardFeedback.js` 从统一请求响应读取 `food_reward: { food, amount }`，访客祝福沿用 `reward_status=granted` 和 `treat_reward`。失败、零奖励和重放响应不排队。
- 根组件的 `FoodRewardFlight.vue` 等所有弹窗及退出过渡结束，再显示中央食物图标和+N；相同种类在等待期间合并。中央停留约0.6秒，再沿弧线飞向可见的“爱的小窝”。手机菜单收起时飞向菜单按钮，短暂提示已放入小窝；减少动态效果时仅显示淡入淡出提示。
- 动画层不拦截点击，不修改库存；奖励在业务事务成功时已经入库。动画刷新后不补播。信箱发送成功后自动关闭，再播放奖励反馈；失败保留正文。
- 情侣双方按北京时间每人每天首封成功发送的新信获得1根猫条，记入发送者的情侣背包份额，合计仍共同展示。用 `pet_activity_rewards` 的 `letter_daily + 用户ID:日期` 唯一键保证并发只领一次；重试、留言、接收信件不再奖励。
- 照片、完成心愿、已完成旅程/预定转旅程均返回实际本次奖励数量；重复内容或再次完成不会重复播动画。
- 测试：`test/e2e/test_food_reward.mjs`、`test_blessing_rewards.mjs`；后端 `test_mailbox.py`、`test_pet.py`。

## 猫咪音效

`useCatSounds.js` 管理用户提供的MP3，原文件在项目外../QN_web_materials/cat/1，发布到public/pet/sounds。浏览器AudioContext解码得到时长：hungry.mp3 1.463秒（开饭）、play.mp3 1.302秒（玩耍）、content.mp3 3.514秒（吃饱）、pet.mp3 1.567秒（摸摸）、meow.mp3 1.451秒（睡醒/返回）。对应原文件依次为cry-of-a-hungry-cat、march-cat-screaming、march-cat-sings-songs、the-cat-asks-to-be-petted、the-sound-of-a-cat-quotmeowquot。

原速、不循环，音量28%，至少间隔8秒，不叠音。首次用户操作后才尝试播放，浏览器拒绝时静默跳过。场景离开视口、页面隐藏、睡觉及上厕所时停止；风格按钮旁提供猫咪音效开关，偏好保存在本机，不控制原有背景音乐。

信箱写信区正文默认4行，常规桌面/手机尺寸无需弹窗滚动；长正文仍可在输入框内滚动，矮屏保留可访问的滚动回退。发送按钮为“寄给ta”，成功自动关闭，失败保留草稿。

发送反馈分两段顺序播放：新信发送成功关闭弹窗后，`public/shared/icons/envelope.webp` 先飞到导航信箱；祝福用 `public/shared/icons/heart.webp` 飞到左侧LOVE。第一段结束后，只有实际获得猫条才播放第二段食物入库动画。两张图使用自制素材，源文件位于 asset/shared/icons；成功但当天无新奖励仍播放送达，重试响应不重复播放。减少动态效果模式使用同样顺序的淡入淡出提示。

库存直接使用主人分账户背包与访客猫条表，不执行旧库存转换。历史奖励流水保留，防止重复领奖；每次启动每位主人三种食物各补足至1，不累加。
