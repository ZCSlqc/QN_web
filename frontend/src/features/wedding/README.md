# 爱的婚礼

## 核验与互动更新

- 管理员核验入口仍为 `/wedding/rig`。腿先绕原外顶点活动（−11～9°），到外转 −11° 才开放裤腿的内顶点；切轴后显示追加角度0～26°，回到0°才允许切回外轴。锁点取当前裤腿原SVG的内顶点（长裤路径14的121.25,102.25，短裤使用对应路径），包含裤腿既有的−3°校准；换轴时整组变换连续，肉腿、裤腿和鞋随动。左右独立，可联动，轴类型和角度随v3配置保存；长短裤分别校准。
- 核验页左右手肘始终无限旋转，角度累计（360、720等），不需要解放其他关节。恢复其他关节限制不清空手肘累计角度。花手整活及科目三中段使用错拍双肘连续两圈，手掌与下袖随小臂转，收势回到同方向的整圈角度，避免倒转多圈归零。
- 婚礼工具栏为鼓掌、祝福、舞蹈、动作、表情、造型，使用emoji图标。走路由地面点击触发。动作侧栏日常8个（正经4/搞怪4）、舞步8个（鬼畜4/正规4）。点舞名只试跳，卡片星标设置默认；初始默认婚礼圆舞。`dancePreferences.js`按登录用户在本机保存默认舞步及自动变脸偏好，刷新保留，无数据库写入。
- 正经日常：挥手招呼、伸个懒腰、点头致意、整理衣领；搞怪日常：摸摸屁股、花手整活、嘚瑟摆胯、开心小跳。`dailyMotions.js`编排抬手、两次挥动、点头及收回等完整动作，不额外拉伸部件。
- 隐藏随机行为12种：休息、眨眼、换脚站立、张望、点头、摇头、整理袖口、摸后脑、点脚、短途慢走、向邻人招呼、停留搭讪；不放进动作选项。各人独立计时，以安静微动为主；邻人可用点头回应，所有状态只在本地。玩家操作和动作期间停止自主行为，动作结束后再等待13～22秒；个人造型决定平稳或活泼倾向。
- 鬼畜舞每4拍按编排切换已缓存的emoji，手动表情及轮盘优先，停舞后恢复原头像；可在舞步面板关闭自动变脸，偏好本机保存。正规舞使用原头像，真人五官继续眨眼和小幅嘴型变化。选舞时只预加载该舞用的3张头像，失败继续以原头像跳舞。
- 伸懒腰先回肩部中立位置、切到已校准的上扬轴、伸展停留，再沿原路径放下；不拉伸部件。
- 表情区默认11张常用头像，加首格幸运轮盘共12格。轮盘先解码六个随机候选，2.5秒由快到慢切换缓存头像，最后结果再显示5秒。手动点选取消轮盘；临时头像轻摇±5°且总头角不超过±20°；减弱动态效果时直接选结果且不摇头。没有新增轮询或数据库写入。

场景分为静态背景画布与人物画布。背景、管家摊位和份子板只在首次绘制、平移视角或窗口尺寸变化时重画；人物、猫咪、杂耍及爱心在上方独立绘制。常规桌面最多 60 帧，窄屏或触摸设备最多 30 帧，动作仍按实际时间推进。昵称和招待点的位置、内容未变化时不重复更新 Vue 和 DOM。

五只猫的坐姿先加载，人物与背景就绪并完成首帧后，再按可见优先逐张加载动作图集。每只猫的动作图集就绪后才自主移动；图集加载失败时保留坐姿及摸猫回应，其他人物和已加载的猫照常活动。

正式婚礼场景已采用核验过的刚性分段人物：`motions.js` 编排自然垂手、放松走路、A形鼓掌、八支舞、八个日常动作和十二种隐藏随机行为。自然站姿左右肩实际下垂角都为35°，以左手为基准，两手掌等高、等距；核验页右肩3°初始校准及45°极限保留。走路小臂仅0～4°，慢走降低节拍和步幅。跳跃整体离地、影子留在地面，结束后归位；减弱动态效果时使用静态姿态。

衣橱分为“妆容”和“造型”。妆容包含发型、头饰、五官、肤色、emoji、动物，发型可选“没有”，头饰单独提供“没有”。造型包含上衣、外套、裤子、鞋子、套装，每项分日常/礼仪；外套可不穿，不提供单穿/叠穿切换。部件和套装卡片都只画衣物，不画头、脖子、手、肉腿或影子；只有上方试穿区显示人物。

服装独立保存 `topStyle/topColor`、`coatStyle/coatColor`、`bottomStyle/bottomColor`，原上衣款式由 `shirt` 指定。外套覆盖上衣和裤腰，换任何部件不替换其他部件；套装才一次配好整身衣服，并保留妆容。`formalStyle/formalColor/matchedBottom` 兼容旧 v3 配置。新郎默认白衬衫和午夜蓝外套，新娘默认纯白婚纱和白色高跟鞋。内搭重绘使用正常合成，避免空遮罩把白衬衫裁成透明。

`/wedding/wardrobe` 按登录账号保存当前换装，`/wedding/wardrobe/outfits` 保存/移除个人搭配，服务端保存部件 ID 和名称，单账号最多 24 套。API 根据登录身份取 user_id，不接受其他用户 ID。读取支持私有 ETag/304；页面会话短时复用读取结果，试穿不提交，相同换装不重复保存，收藏不覆盖当前换装。

`shenqidayang` 默认沉稳女孩，长发、轻摇和安静停顿；`lqc` 默认活泼男孩，短发、短袖，空闲时更常伸展与招手。账号已保存的外观优先，昵称变化不改变人格。

庭院人物来自 `/wedding/people` 的真实账号名单，编号模拟宾客已移除。所有名字均使用数据库昵称，未填写则使用用户名，页面标题也读取新郎/新娘的数据库名称。新郎、新娘、`shenqidayang`、`lqc` 读取各自保存的外观，当前登录者直接接管对应人物，不重复生成。名单仅在进入页面时读取，使用短时缓存和 ETag；其他人物的位置、动作和状态由各浏览器本机独立运行，不轮询、不广播，不做场景实时同步。屏幕外人物暂停自动活动并跳过绘制。

服务 NPC 共两位：花礼管家与二维码左侧的招财小哥。小哥固定在 `(1180,265)`，与管家脚底等高，交替抛接元宝、金条、钱币三张素材，并在二维码牌上方展示“祝大家财源滚滚，事业有成，份子拿来！”；话语跟随牌子的位置及画布缩放。抛接点使用刚性手臂的实际掌心，运动不拉伸部件。三张自制道具归档在 `asset/wedding/original/juggling/`；`npm run assets:original` 从透明图集重建，不依赖临时导入目录。不可见时不额外驱动画布，减弱动态效果时静止展示。

份子板与花礼摊位统一在背景阶段绘制，人物始终绘制在它们上方。份子板 DOM 仅保留随画布缩放的透明点击区域，点击仍打开收款码原图。花礼管家、摊位背景和领取点共用 `(310,265)` 锚点，同步右移；份子板位于 `(1295,255)`。

服装卡片进入可视区域才加载，只取正面衣物。不同预览和主场景共享最多 160 项的图片解码缓存，各实例保留自己的引用；关闭一个预览不会清空其他人物的图片。进入庭院直接加载用户已保存外观，避免先加载默认来宾再换一次素材。

右下角沿用全站音乐组件，婚礼页也保持同一 audio 元素；音频位于 `shared/audio/city-of-stars.mp3`，`preload="none"`，点击后才下载。移动端控件位于操作栏上方的右下侧。`/wedding/rig` 带管理员专属路由权限，可从后台“人物核验”进入；普通用户即使有婚礼页权限也不能进入。`/rip` 不注册开放路由。

`headwear.js` 定义头纱、花圈、皇冠、帽子、礼帽、绅士帽与不佩戴。头饰前层固定在头发之后、前景下臂之前；全部跟随头部锚点与转角，后披纱保留对应后层。旧 `veil` 布尔值兼容迁移到 `headwear`。帽檐、冠底与花圈弧线贴合原头部轮廓，不拉伸。

招待处领取物品通过 `scene.carry` 预加载并绑定实际手掌，`heldItems.js` 使用素材归一化握点、统一比例，手持物在原尺寸上放大 1.5 倍并保持握点贴掌。花束、饮料、小食单手拿，礼盒、餐盘双手托；手掌覆盖握处，背面物品和握持下臂放到身体之后。走路及腰部转动保持握点，主动鼓掌、跳舞等动作暂存物品，结束后恢复；放回即清空。新娘和部分来宾默认带物品。

`/me.wedding_role` 由服务器按管理员账号决定，`weddingIdentity.js` 只接受管理员的 groom/bride。对应用户直接控制场景已有的新郎或新娘，访客另建来宾。默认绑定李琪淳/郑丹妮，可由 `QN_WEDDING_GROOM_USER`、`QN_WEDDING_BRIDE_USER` 配置；昵称变化不改身份。

`ambientPeople.js` 给每个人独立的下一次动作时间、停顿、短路径和步速；来宾在原站位附近伸展、抓痒、摇摆、挥手、缓慢走动。新郎/新娘留在主位附近，你的人物空闲 12 秒后才做轻动作，用户输入会立即接管。emoji 表达临时替换可见头像 5 秒，永久造型保留，支持期间换装和最新选择覆盖旧选择。

`npm run assets:wedding` 从原版 SVG 模板和原 PNG 配色生成 `public/wedding/kenney_modular-characters/Derived`，当前 217 个 SVG，包括独立上/下肉臂、上/下长袖、八类礼仪服装与两类日常外套、裙摆、前后头饰，以及五类礼仪鞋的四种配色。新鞋包括系带皮鞋、蝴蝶结礼鞋、细跟/粗跟/绑带高跟鞋，沿用 94×42 原鞋坐标框和脚踝锚点，不拉伸鞋或腿。`Derived/catalog.json` 记录来源和切割圆心。上衣在裤腰之下，外套在裤腰之上；后披纱在上袖与衣身之前。

下臂遮挡：每只手臂的 `forearmLayers` 按 front/back 两个朝向分别保存 auto/front/back。auto 沿用原顺序；front 将小臂、手掌、下袖作为完整组在头发及自动下臂之后绘制；back 将完整组在腿、鞋和所有衣物之前绘制。上臂/上袖、脖子、上衣、裤腰等原顺序不变。核验页选择肩或肘后，可用“下臂遮挡：自动/最前/最后”调整；开左右联动时两侧同步，切换朝向后使用对应朝向的设置。配置会随 JSON、本机保存和衣橱预览保留。

当前普通人物默认层级（底→顶）：正面为肉腿→鞋→裤腿→上臂/上袖→脖子→上衣→裤腰→头/头发/五官→下臂组；背面将默认下臂组放到头/头发之前。组内始终是小臂→手掌→下袖。特殊“最后”整组位于所有人物部件后方，“最前”整组位于所有人物部件前方；对应画布绘制时分别最早和最晚执行，统一继承上身平移和腰部扭动，不修改骨骼角度。

`test_arm_occlusion.mjs` 验证 36 种朝向/袖长/肩姿态/层级组合，检查绘制次序及手掌与裤腰重叠像素；同时验证左右手及正背面独立保存，切换层级时肘点和角度保持一致。

成果核验页已替代绑定调试流程：`WeddingRigView.vue` 入口显示 `WeddingReviewView.vue`，工具分为动作/穿搭/保存；不提供绑定坐标、骨骼锁定或确定姿态按钮，已有绑定仍随配置保存。画布所有旋转点及左右联动可直接操作；导入兼容原 v3 配置，保存沿用本机存储键。

## 固定动作

- 走路：点击地面或方向键选择位置，点击走路按钮可以结束手势；有脚步交替、双臂摆动。
- 鼓掌：肩膀固定、肘部弯曲，两手在胸前开合，闭合时两掌边缘接触且不交叉。每秒两次，持续2.6秒。
- 跳舞：鬼畜4支为牙线舞16秒、科目三15.5秒、闪身步16.6秒、抖肩舞15秒；正规4支为婚礼圆舞13.3秒、藏族弦子风格13.8秒、蒙古族舞风格17.1秒、傣族舒展风格15秒。每8拍换段，有起势、段落变化和收势。螃蟹舞及小鸡舞移出选项，旧动作ID映射到新版。
- 编排在`choreography.js`：牙线舞直臂与胯反向，一轮前一轮后；科目三翻脚接花手；闪身步保留垂手造型，短促侧闪、顿步、回身并摇头晃脑；抖肩舞快速肩腰抖动。正规舞分别采用三拍进退、连步摆袖、肩腰开合、柔缓错拍抬臂。民族舞是现有骨骼上的风格化编排，保留固定手型和整段腿素材。
- 肩仍遵守左0～35°/右3～45°及原上扬范围，头±20°、鞋±5°、腰±10°。腿从原外轴−11～9°连续接入裤腿内轴，追加不超过26°，编排常用追加2～15°，脚底补偿保持接地。手掌锁在小臂，素材不拉伸。跳跃保留独立重力抛物线。
- 民族风格参考：[昌都弦子舞教学推广](https://lyfz.changdu.gov.cn/cdslyj4/c101252/202601/277fd123931848bfa2ec41d547ce9493.shtml)、[蒙古族传统舞蹈公开课](https://www.imac.edu.cn/html-wdxy/djsz/20240626/30256.shtml)、[云南非遗孔雀舞](https://www.ynich.cn/item/38.html)。页面不加载外部教学视频或音乐。
- 跳跃：`jumpPhysics.js` 使用 `h=v₀t−gt²/2`、`v=v₀−gt`；330源像素/米、重力9.81米/秒²，起跳速度2.32米/秒，腾空约0.473秒、最高约0.274米。0.32秒准备及0.34秒落地恢复，脚接地时以旋转后的鞋底边界校准位置，腾空期间根节点严格走抛物线，不叠加通用缓动；阴影留在地面，名字跟随人物。没有缩放或临时膝盖。跳跃途中点击地面或动作会保留最后一个请求，完成落地再执行；拿物品也不会把半空中的人物拉回地面。
- 教学参考：[GoNoodle牙线舞](https://www.gonoodle.com/videos/W2gVjX/how-to-floss)、[Handsome Dancer原版抖肩舞](https://www.youtube.com/watch?v=nBHkIWAJitg)、[JTBC螃蟹舞示范](https://www.youtube.com/watch?v=01iz9kmvbxg)、[GoNoodle小鸡舞](https://www.gonoodle.com/videos/Zwm9zw/squatchy-move-chicken-dance)。重力公式参考 [NASA弹道运动](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/ballistic-flight-equations/)。只新增本地角度编排，不加载这些视频或新增音频请求。
- 祝福：胸前送出两颗爱心，分别沿曲线飞到琪琪、妮妮胸前。每轮只允许一组在途爱心，连续点击不堆叠。没有新增文字留言、库存奖励或后端写入。

### 朝向与镜像

所有姿态（坐、观察、趴卧、举爪、走路、小跑）都绕脚底锚点水平镜像，名字与爱心不翻转。停下保留行走方向；被摸和收到祝福朝向访客，社交到达后双方相互关注；瓜瓜退让后观察来人。安安趴卧时不自主转向，六一优先关注附近访客，花花关注同伴，黑黑在附近对象间切换注意力。

静止观察有18世界单位水平死区、1秒转向冷却；行走采用8单位死区和220毫秒冷却。只在需要时重绘；减少动态模式停止自主观察，保留用户主动互动的朝向回应。当前仍使用原图左右镜像，不是新生成的侧脸或背面动作。

## 范围编辑与自制素材

管理页入口“可移动范围”打开 `/wedding/area`，仅管理员可访问。支持拖点、数值调整、加点、删点、撤销、缩放、导入导出 JSON 和自动草稿。试走复用 `createNavigation` 与婚礼一致的边界与寻路，但独立于正式场景。本机 `npm run dev` 下点“保存到本机”，会经由 Vite 本机保存服务直接更新 `frontend/src/features/wedding/walkable-area.json`；服务校验管理员身份和多边形，原文件备份到系统临时目录后原子替换，再进入婚礼即可使用。部署版只保留导出功能，替换前端 JSON 后重新构建。非法导入不会覆盖当前点位。

自制素材使用 `asset/wedding/original/catalog.json`；饮料、小食、中餐、甜品各 6 件，花礼两组各 6 件，杂耍 3 件、婚戒 1 件，共用图标 4 件存于 `asset/shared/icons/`。表情首页为老虎机和 11 个特色头像。管家只做轻微点头、整衣领等安静动作，花篮放在左侧桌面避免遮挡。

单手物品在领取时一次性随机分配左右手，不修改公共素材清单；手持期间、动作恢复后保持同一侧。双手礼盒和餐盘保持双手。气球将肩部切到上举分支，上臂和小臂一起抬起，手肘微弯 10°，握住绳尾，同样保留正反面遮挡层级和 1.5 倍物品尺寸。

头饰下方分女士、男士两行，每行 4 款：女士为头纱、花圈、皇冠、蝴蝶结；男士为帽子、礼帽、绅士帽、贝雷帽。“没有”位于独立按钮，不占格子，分组不限制人物选择。新增的蝴蝶结和贝雷帽延用原 SVG 头部坐标和挂点，正反面各一张小 SVG，按需加载。

默认五官使用现有 4 组搭配，在 `wedding_face_defaults` 中每人随机一次后保留，不会因重进页面或缓存失效换脸。新郎不分配随机默认脸，已保存的自选五官优先；管家和杂耍小哥也使用入库的默认脸。后端仅在缺少配置时插入，仍一次读取人物列表、本地独立演出，没有场景状态同步或轮询。

礼花使用向身体外侧伸出的单手持有姿势，左手围绕握点镜像图片，喷口始终向外，手掌与小臂固定关系不变。新人初始 y=259，相比以前上移 45 单位，名字保持头顶居中，标题收紧间距避免重叠。底部工具栏背景 alpha=0.2；管家桌面上移并移除绿礼盒，花篮与红礼盒最终下移 5 个本地像素。
