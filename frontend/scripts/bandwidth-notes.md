# 图片传输优化

- 好朋友展示图使用480px高的WebP副本；原PNG保留。更新原图后运行 `node frontend/scripts/optimize-pet-friends.cjs`。
- 猫咪只预加载当前风格的行走帧，姿势和食物道具在使用时加载。
- 旅程缩略图进入可视区域后才请求；大图只加载当前张并最多预取下一张，开启省流量模式时不预取。当前详情关闭后释放临时图片地址。
- 相册和旅程大图使用最长边1920px、质量85的WebP预览；原图不改动。既有照片首次查看时自动生成副本，之后复用。删除上传照片时一并删除预览文件。
- 私密旅程预览仍鉴权并使用 `private, no-store`。不缓存到共享CDN。
- Vite开发/预览服务的公开图片采用ETag条件缓存；文件未变化时返回304，不重传文件体。更新文件会产生新ETag，避免长时间缓存旧素材。
- GeoJSON和SVG支持gzip。API、动态模块和音乐Range请求不经过这层静态处理。
- 将 `dist` 放到其他Web服务器时，应在该服务器配置静态缓存和gzip/Brotli；Vite插件不会随静态HTML自行运行。

## 实测（2026-10-28）

本地Chromium、相同冷缓存场景：进入主人猫咪页并滚动至好朋友图片，统计资源编码后字节数（不包含HTML、JS、音乐）。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 猫咪页图片 | 8,167,922 bytes | 537,860 bytes |
| 四张好朋友图片 | 6,926,220 bytes | 65,754 bytes |
| 城市GeoJSON | 3,869,209 bytes | 1,255,382 bytes（gzip） |

猫咪页图片减少93.4%。这不是全站总流量或Sakura Frp计费流量的保证；首次访问其他页面、切换风格、查看照片仍会产生相应传输。
详细资源清单在本地 `artifacts/bandwidth/before.json` 和 `after.json`。
